## Coordinator decisions (spec lines for the fix commit)

1. **Request framing (U11, U12).** A command body is exactly one JSON object in UTF-8; trailing data,
   invalid UTF-8 and member names that differ from a documented field only by case are 400
   `invalid_json`. Exact duplicate names stay implementation-defined (the explorer did not claim them).
   Free-form `payload` and `result` members are not checked for names.
2. **Seconds-valued inputs (U13, U14, U16).** Every seconds field (`delay_seconds`, nack `delay_seconds`,
   `extend_seconds`, `lease_seconds`, `backoff.base_seconds`, `backoff.max_seconds`) and `max_attempts`
   accepts at most 2 147 483 647; larger values are 400. Negative `delay_seconds` stays accepted as "due
   now" (spec silent; not claimed). Computed backoff saturates instead of wrapping; a retry is never
   scheduled before the nack.
3. **Names and storage limits (U14).** Queue names are 1–128 characters. A duplicate name is the only
   409 `queue_conflict`; other store errors are 500; out-of-range values are 400 before the store sees
   them, on create and on PATCH.
4. **Retention (U15).** `retention_hours` is 0–1 000 000 (≈114 years); larger values are 400. The
   sweep's comparison must not overflow for any stored value, so a legacy row cannot halt the sweep.
5. **Backoff cap (U17).** `backoff.max_seconds`, when present, is a positive cap on each computed wait,
   and at least `base_seconds`. Absent means uncapped, as today; the default is A1's question for E04.
6. **Nested PATCH (U18).** `PATCH /v1/queues/{name}` merges the `webhook` object member by member, like
   RFC 7396: an omitted member keeps its value; `"url": ""` disables notifications; `null` keeps both.
