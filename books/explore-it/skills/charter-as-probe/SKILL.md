# Charter as probe

Draft for execution against queuelet. In this arc follow [the protocol](../../exploration/PROTOCOL.md); operate within the export and assigned charter.

## When to use

A subsystem to learn, a risk to settle or an exploration request too broad for one session.

## Inputs

The question, system boundary, instruments, data/models, known evidence and permitted budget.

## Procedure

1. Choose one target and one kind of information. Use: Explore <target> with <resources> to discover <information>. Name actual instruments: source, spec, raw API client, logs, database views, partner records or models.
2. State “I predict …” and its source: spec, code with a pointer, model cell, prior surprise or risk hypothesis. State “I would be wrong if …” as an observable result before probing.
3. Match technique to question: recon for an unknown surface, variation for inputs, an oracle for disputed outputs, sequence/state for ordering, entities/data for dependencies or ecosystem for neighbours.
4. Include wall-clock budget and reading/probing/writing allocation. Queuelet charters use 60 minutes; elsewhere use the assigned budget. Account for reset and evidence-writing cost.
5. Check breadth: a package sightseeing list lacks a learning question; a fixed expected response alone is a check. Let observations shape the next probe within the target while retaining earlier predictions.
6. Backlog adjacent questions instead of expanding the charter. In the queuelet arc the coordinator owns it; the explorer may propose a narrowed follow-up but cannot widen the assignment.

## Output

One charter: target/resources/information, prediction, source, refutation condition, probe family, permitted operations, budget and intended evidence.
